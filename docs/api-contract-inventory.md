# ConfluencePS API contract inventory

**Recorded:** 27 July 2026

**Scope:** The 45 functions exposed when the source manifest is imported after applying its default `Confluence` command prefix. This includes the 22 intended commands in `ConfluencePS/Public` and 23 implementation helpers exposed by the source manifest's wildcard exports. The compiled `Release` artifact narrows the export list to the 22 Public commands, so the source/package difference must remain visible until explicit source exports replace the wildcard in Phase 9 Task 58.

**Purpose:** Define the current Confluence REST API v1 and Data Center contracts, the operation-specific Cloud REST API v2 migration target, pagination and conversion work, test coverage, and least-privilege security boundary. This is an inventory, not an assertion that every v1 operation has v2 parity.

## Contract status

- **Current v1:** The route used by the code today. Cloud resolves it below `/wiki/rest/api`; Data Center resolves it below its configured `/rest/api` context.
- **V2 migration:** A supported v2 route is named explicitly. **Parity gap** means Cloud v2 does not provide an equivalent operation or the current public contract needs additional resolution or response adaptation.
- **Pagination:** Current v1 collections use `start`, `limit`, `size`, and body `_links.next`. V2 collections use opaque `cursor` values and `Link` or body `_links.next`; they must not be treated as numeric offsets.
- **Tests:** “Baseline only” means the command is recorded by the public-command coverage baseline but has no focused unit test.
- **Internal export:** A helper is callable from a source-manifest import because `FunctionsToExport = '*'`, although the current compiled release excludes it. It is not a supported product command and should be removed from the source public surface by Phase 9 Task 58.

## V2 migration decisions

1. Do not replace `/rest/api` with `/api/v2` globally. Route by operation and deployment.
2. Keep Cloud v1 dependencies explicit for attachment upload/update, label mutation, CQL search, content-body conversion, system information, attachment download, and space deletion until a tested replacement exists.
3. Implement v2 cursor pagination centrally before migrating any collection command. Preserve filters while following only trusted relative or same-tenant next links, and detect repeated cursors.
4. Add dedicated v2 converters rather than forcing v2 responses through v1 assumptions. Public `ConfluencePS.Page`, `Attachment`, `Space`, `User`, and `Version` types must remain stable unless a separately approved breaking change is made.
5. Resolve space keys and label names to v2 numeric IDs deliberately and cache only permission-safe metadata.
6. Treat storage bodies, filenames, attachment bytes, labels, user data, hierarchy, permissions, and diagnostic responses as untrusted or sensitive at every boundary.

## Security classification

| Class | Commands | Required control |
|---|---|---|
| Stored content | Page create/read/update/delete, child pages, and storage conversion | Content permission checks, untrusted-markup handling, version conflict protection, and high-impact confirmation for permanent deletion |
| Attachments | Add/get/download/update/remove attachment | File/path/size validation, trusted download hosts, redirect credential stripping, anti-CSRF upload header, no automatic execution, and delete/purge separation |
| Users | Page/space/version converters and generic transport responses | Account-ID migration, data minimization, permission-aware fields, and no personal data in logs/fixtures |
| Space permissions/admin | Space create/delete and generic transport | Least-privilege administrative permission, explicit target validation, `ShouldProcess`, auditability, and protection against accidental whole-space deletion |
| Admin Key | No dedicated command exists; `Invoke-ConfluenceMethod` can call arbitrary routes | Do not add implicit admin-key acquisition or activation. Any future support needs a separate high-risk contract, explicit user intent, short lifetime, and dedicated audit/redaction tests |
| Authentication/transport | `Set-ConfluenceInfo`, `Invoke-ConfluenceMethod`, and exported internal transport helpers | HTTPS Cloud enforcement, trusted-host routing, redirect stripping, secret redaction, no token persistence, and removal of internal helpers from exports |

## Test gaps that bound later work

- Nine intended commands have focused unit files; the remaining intended commands are represented only by the public-command coverage baseline and/or integration suites.
- Existing integration suites exercise current v1 behavior. They do not prove v2 routing, cursor pagination, v2 converters, OAuth scopes, or Cloud/Data Center route separation.
- No live integration run was performed for this documentation-only task because no disposable Cloud/Data Center credentials were supplied.
- Each Phase 7 migration task must add Cloud v2 fixtures, retain Data Center v1 fixtures, and update this inventory when a parity gap is resolved.
